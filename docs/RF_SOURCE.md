# Random Forest as the source of S (rounds 19, 19b and 19c)

**Status (round 19c): the DEFAULT.** `S_SOURCE = "rf"`: the app uses the Random Forest prediction `s_prob` as the site match S. `S_SOURCE = "rules"` (the expert rules themselves) stays available. If `s_prob` is missing or incomplete in the saved scores the app falls back to the rules automatically and `/health` shows a warning.

## The hybrid, in order
1. **Expert rules** (`pipeline/score_sites.py`): every square x species pair gets `s_rule` (0 to 1) from fixed rules (elevation, slope, soil, wetness, zone). Hard gates make S = 0.
2. **Random Forest** (`pipeline/train_rf.py`): since round 19b `s_prob` is the out-of-fold prediction of a Random Forest **regressor** that learns the rule score S itself (0 to 1), from the pair table (`make_pair_table.py`: raw site values and raw species traits). It is clipped to 0..1. The round 19 **classifier** (yes/no, S >= 0.50) is still trained and reported (`rf_classifier_oof.csv.gz`), but it no longer makes `s_prob`.
3. **Hungarian matching** (`pipeline/matching.py`): unchanged. It uses whichever S the setting names.

## How the probabilities are made
- **Spatial out-of-fold.** The squares are cut into blocks of 10 x 10 grid cells (about 1 km). A block is never split between training and test (GroupKFold, 5 folds, the same blocks and seed as the model comparison). Every pair gets its prediction from the model of the fold where its block was the test part, so no pair is scored by a model that trained on its neighbourhood (`tests/test_rf_source.py` checks this).
- **Hard gates kept.** Where the rule S is 0 (outside the zone, outside the elevation range, beyond the slope hard stop) `s_prob` is set to 0 and the pair stays rejected. The zone is a gate, not a feature. Eligibility with `S_SOURCE = "rf"` is `s_prob >= 0.50`.
- **Model files.** `data/processed/models/` (git-ignored): `rf_site_suitability.joblib` (the regressor, trained on all pairs), `rf_site_suitability_classifier.joblib`, and `rf_site_suitability_meta.json` (training date, dataset hash `34964a09fe44`, features, settings, out-of-fold error). Regressor: 200 trees, no depth limit, at least 2 pairs per leaf (chosen by out-of-fold error: 5 per leaf gave MAE 0.00088, 2 gave 0.00059), seed 42.
- **Order of the pipeline:** `score_sites.py` -> `make_pair_table.py` -> `train_rf.py`. Running `score_sites.py` again empties `s_prob`; run `make_pair_table.py` and `train_rf.py` again afterwards.

## The setting and the fallback
`S_SOURCE` in `pipeline/matching.py` ("rf" | "rules", default **"rf"**); the environment variable `OS_S_SOURCE` or `API_CFG["s_source"]` in `api_v2.py` override it without editing code (an explicit argument wins). With "rf" the prediction replaces S everywhere S is used: `mt.weights` (W and the 0.50 eligibility test), `/rank`, `/grid`, `/areas/rank`, `/rank/area`, `/nearest-viable`, palettes, plans and the matching. The hard limits (zone, elevation, steep slope) always apply first: where the rule S is 0, `s_prob` is 0 and the pair stays rejected.

**Fallback.** If the saved scores have no `s_prob` column, an empty one, or any gap (a fresh clone, or `score_sites.py` was run again alone), `matching.load_context` uses "rules" instead and carries a warning (`Context.s_warning`). `GET /health` then shows `s_source: "rules"`, `s_source_requested: "rf"` and `s_source_warning` ("The saved scores have no complete Random Forest prediction ... run: python scripts/rebuild_scores.py"). Empty values are never used as zeros.

**Screens.** With the source "rf", "Why this score?" has the line "Suitability from the Random Forest: 0.83. Rules check: passed." (and a note); with "rules" it is not shown. Help and the user guide say: "Site suitability is predicted by a Random Forest trained on the expert rules. Hard limits (zone, elevation, steep slope) always apply first." `GET /health` shows the model's training date and hash.

## Rebuilding, and what a fresh clone needs
`python scripts/rebuild_scores.py` runs `score_sites.py` -> `make_pair_table.py` -> `train_rf.py` (in this order) and prints the S_SOURCE it ends with. `data/processed/scores/` and `data/processed/models/` are **git-ignored and not tracked** (`site_scores.csv` is 115 MB, `site_scores.db` 129 MB, the model 50 MB: over GitHub's 100 MB file limit), so a fresh clone does not contain `s_prob` and does not start without scores. After `scripts/rebuild_scores.py` (several minutes) it runs in "rf" mode. To run a fresh clone in "rf" mode WITHOUT retraining you would have to track a compact file (for example `point_id, species_id, s_prob` as a gzip of a few MB) and add a loader step that fills `s_prob` from it; that is not built. The training is deterministic (seed 42), so a rebuild gives the same values.

## What the numbers say (graded slope mode; `data/processed/rf_vs_rules_report.txt`)
- **Regressor, out-of-fold (spatial folds):** mean absolute error 0.0006, R-squared 0.9998. A Decision Tree regressor on the same folds: 0.0006 and 0.9997. They are equal within the spread between folds; the forest is not clearly better than one tree. (On the pairs the rules allow: MAE 0.0007, R-squared 0.9992.)
- **Eligibility:** rules 257,869 pairs, forest 257,929. 168 pairs change (0.05%): 54 eligible only by the rules, 114 only by the forest (they sit next to the 0.50 line).
- **Rank agreement:** Spearman correlation of S and `s_prob` among the pairs the rules call eligible: 0.994 (per species 0.992 on average, lowest 0.969 for Banaba). The top-20 squares per species overlap by 15.4 of 20 on average (18 of 45 species have the same 20); the rules tie on the top S for a median of about 2,300 squares per species, so the exact top 20 is mostly the tie-break.
- **Matching (Hungarian and greedy tie in both modes):** the plans made with the forest share most squares with the rules' plans (for example 169 of 300 for urban, 219 for planting, 15 of 16 blocks). Judged by the rules, the forest's plans lose between 0.00% and 0.04% of total W (all six cases: urban, planting, watershed; points and blocks); judged by the forest, the rules' plans lose about 0.03%.
- **Success test of round 19b (the forest's plans, judged by the rules, lose less than 2% of total W): MET**, by a wide margin.
- **Round 19 classifier, for comparison:** accuracy 0.9996 (Decision Tree 0.9995). Its plans lost 5 to 10% of total W when judged by the rules, because a yes/no probability cannot tell S = 0.55 from S = 1.0; that is why the regressor replaced it for `s_prob`.

## What it is and is not
The forest is trained on **expert-rule scores**, so it generalises the rules: it almost copies them (R-squared 0.9998) and smooths their sharp edges a little. It is **not an independent measurement of survival** and has no field data behind it. Its very small error only shows that the rules are easy to learn from the raw features. Because it copies the rules, using it changes the results very little; it does not add information. Nothing here validates the rules against real planting results.
